사용자가 준 요청: $ARGUMENTS

(비어 있으면 **직전 대화에서 사용자가 마지막으로 요청한 내용**을 대상으로 삼는다.)

이 요청을 바로 실행하지 말고, 먼저 **의도를 확정**한다. 목표는 질문을 많이 하는 게 아니라
**왕복 횟수를 최소로 줄이면서 확신을 얻는 것**이다.

## 1. 먼저 스스로 조사한다 (질문하기 전에)

물어보기 전에 코드베이스에서 알아낼 수 있는 건 알아낸다. **파일을 읽으면 답이 나오는 걸 사용자에게
묻지 않는다** — 그건 구체화가 아니라 떠넘기기다. 관련 파일, 기존 패턴, `CLAUDE.md` 규칙,
최근 핸드오프를 먼저 본다.

## 2. 빈칸을 찾는다

아래 중 **결과물을 실질적으로 바꾸는 것만** 고른다:

| 항목 | 물어볼 가치가 있는가 |
|---|---|
| **목표** — 이걸 해서 무엇이 좋아지나 | 없으면 항상 물어본다 |
| **성공 기준** — 무엇을 보고 됐다고 판단하나 | 애매하면 물어본다 |
| **범위** — 어디까지 손대나 | 넓게/좁게 해석이 갈리면 물어본다 |
| **제약** — 건드리면 안 되는 것, 지켜야 할 것 | 위험한 영역이면 물어본다 |
| **취향** — 이름, 스타일, 배치 | **묻지 않는다.** 합리적 기본값을 고르고 한 줄로 알린다 |

## 3. 한 번에 묻는다

호스트가 제공하는 선택지 질문 수단(Claude Code에서는 `AskUserQuestion`, Antigravity에서는 `ask_question`)으로 **2~4개를 한 번에**
묻는다. 객관식으로, 각 선택지에 그걸 고르면 무엇이
달라지는지 한 줄씩 붙인다. **권장안을 첫 번째에 두고 근거를 적는다** — 사용자가 판단할 근거가 있어야
"아무거나"라는 답이 안 나온다.

**연속 심문 금지.** 1회로 부족하면 최대 1회 더. 그 이상 필요하다면 질문이 잘못된 것이다 —
남은 불확실성은 가정으로 명시하고 넘어간다.

사용자가 비개발자일 수 있다. 전문 용어를 쓸 때는 무엇을 뜻하는지 한 줄 덧붙인다.

## 4. 되읽는다

답을 받으면 **실행 전에** 이렇게 정리해 보여준다:

```
목표: <한 줄>
성공 기준: <무엇을 보고 됐다고 판단할지>
할 일: 1) … 2) … 3) …
안 할 일: <범위 밖이라 손대지 않을 것>
가정: <물어보지 않고 정한 것 + 왜>
```

되읽기 한 번이 질문 다섯 개보다 정확하다. 사용자가 여기서 "아니 그게 아니라"라고 말하면
그때 고치는 게 가장 싸다.

## 5. 진행

승인되면 바로 실행한다. 작업이 크거나(파일 여러 개, 여러 세션에 걸칠 일) 나중에 되짚을 결정이
있으면 `/devkit:spec` 으로 문서를 남기자고 제안한다 — 다만 강요하지 않는다.
